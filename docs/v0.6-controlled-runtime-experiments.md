# v0.6 Product Design — Controlled Runtime Experiments

## Summary

v0.5 lets an Agent preserve a runtime baseline and verify what changed after normal development work. v0.6 adds the first **controlled runtime experiment**: an Agent may temporarily enable the existing waterfall instrumentation seam under a finite, owned lease, collect factual traces, and return the runtime to its previous uninstrumented state.

The milestone goal is:

> An Agent can request a short waterfall profiling experiment, obtain the required authority, observe traces that belong to that experiment, and rely on timeout/ownership cleanup so instrumentation cannot be left enabled indefinitely.

This is intentionally narrower than “Agent can mutate Cordis”. v0.6 controls one already-shipped reversible seam only.

## Product progression

```text
v0.4  Agent can inspect runtime facts
v0.5  Agent can verify before/after runtime facts
v0.6  Agent can perform one bounded runtime experiment
```

## Why raw profiler mutation is not enough

The existing Human Profiler has a simple boolean-style mutation surface. That was appropriate while a person owned the visible panel, but it is not an Agent contract.

A direct Agent `enable()` / `disable()` pair would leave unanswered:

- who owns the instrumentation seam now;
- what happens if the Agent crashes or disconnects;
- whether one Agent can disable another Agent or Human session;
- whether a Human can emergency-stop an Agent capture;
- how long profiling may remain enabled;
- how DSH obtains user permission;
- how an external MCP client obtains mutation authority;
- how traces from the new experiment are distinguished from older retained traces.

v0.6 solves those lifecycle/authority questions before exposing mutation.

## Core architecture

```text
                         Cordis runtime
                              │
                    Waterfall controller
                              │
                              ▼
                 WaterfallExperimentCoordinator
                 single instrumentation owner
                  /          |           \
                 /           |            \
                ▼            ▼             ▼
        Human Profiler   DSH Agent      external MCP
        visible control  native tools   capability + auth
                             │              │
                             ▼              ▼
                        ctx.approval      bearer token
```

The coordinator is the only layer allowed to mutate the low-level waterfall instrumentation controller after v0.6 lands.

## Control state

Machine-facing state is factual, not inferred. Conceptually:

```ts
type WaterfallControlOwner =
  | { kind: 'none' }
  | { kind: 'human' }
  | {
      kind: 'agent'
      leaseId: string
      source: 'dsh' | 'mcp'
      startedAt: number
      expiresAt: number
    }

interface WaterfallExperimentStatus {
  generatedAt: number
  instrumentation: 'disabled' | 'enabled' | 'conflict' | 'unsupported'
  owner: WaterfallControlOwner
}
```

The final shared contract may add explicit ended/busy reason enums, but these rules are fixed:

- `enabled + human` means the Human Profiler owns the seam;
- `enabled + agent` means exactly one live Agent lease owns it;
- `disabled + none` is the normal idle state;
- `conflict` / `unsupported` remain controller facts and are never hidden by an optimistic lease status.

## Agent lease contract

### Start

Conceptual operation:

```text
startWaterfallExperiment({ ttlMs? })
```

A successful start returns an opaque `leaseId`, source, start time, and expiry.

Initial defaults:

```text
defaultTtlMs = 15000
maxTtlMs = 60000
```

There is no infinite TTL. A configured/requested TTL must be positive and finite, and a request may not exceed the configured maximum.

Start succeeds only when the instrumentation seam is currently idle and supported. Otherwise it returns a structured no-mutation result such as busy/conflict/unsupported.

### Stop

Conceptual operation:

```text
stopWaterfallExperiment({ leaseId })
```

Stop mutates only when the supplied id equals the current live Agent lease. A stale or wrong lease id cannot disable a Human session or a later Agent lease.

Stop does not require a second user approval because it only ends the exact active Agent-owned experiment.

### Timeout

At expiry, cleanup checks that the same lease still owns the coordinator, then disables through the low-level controller.

If ownership changed, cleanup does nothing.

If the controller reports conflict, cleanup preserves fail-closed semantics and does not overwrite the competing dispatch implementation.

### Human emergency stop

The Human Profiler remains the ultimate local safety surface.

When an Agent lease is active, the UI must identify that profiling is Agent-owned and expose an explicit stop action. Human stop ends the lease immediately. A later Agent stop call observes that the lease is no longer active and must not mutate anything else.

Human enable cannot silently steal an active Agent lease; the Human must stop the Agent capture first.

## Experiment trace association

The bounded profiler store may already contain traces from earlier Human profiling. An Agent experiment therefore needs an exact association rather than a timestamp guess.

A trace created while an Agent lease owns instrumentation receives:

```text
experimentId = leaseId
```

Human-created traces have no experiment id.

`profilerTraces` adds an optional exact `experimentId` filter. This gives the Agent the loop:

```text
start → leaseId
  ↓
exercise runtime
  ↓
profilerTraces({ experimentId: leaseId })
  ↓
stop / timeout
```

The filter does not make the trace store lossless. Existing `bounded / retained / matched / returned / truncated` semantics still apply, and late `next()`/settlement facts may update an already-tagged retained trace after the lease ends.

## DSH Agent authority

### Keep `CordisRuntime` read-only

`CordisRuntime` remains the DSH inspection Provider. It may expose a read-only experiment status method, but start/stop do not become inspect methods.

### Dedicated DSH mutation tools

The DSH-facing mutation surface is a dedicated tool pair:

```text
cordis_start_waterfall_experiment
cordis_stop_waterfall_experiment
```

The start body requests a one-shot decision through DSH's existing `ctx.approval` service before touching the coordinator. The request uses the real calling Agent/call id and a human-readable reason such as “Enable Cordis waterfall instrumentation for up to 15 seconds.”

Only `allowed-once` proceeds. Rejected, cancelled, unavailable, missing service, or missing Agent identity all fail closed before instrumentation changes.

The start tool asks inside its own execution before mutation instead of trusting a reorderable `tools/pre-execute` listener to be the mandatory gate. DSH's approval service still owns routing/audit/outcome semantics.

The stop tool requires the exact lease id but no new approval.

## External MCP authority

External MCP has no authentic DSH Agent/session owner, so it does not use or emulate `ctx.approval`.

Mutation capability is disabled by default.

Proposed config:

```yaml
- id: dsh-cordis-devtools
  config:
    mcp:
      enabled: true
      port: 43127
      token: ${CORDIS_DEVTOOLS_MCP_TOKEN}
      experiments:
        enabled: true
```

Behavior:

- ordinary read-only MCP remains available with the existing v0.5 defaults;
- configuring `token` protects all MCP requests with `Authorization: Bearer ...`;
- enabling MCP experiments requires a non-empty token;
- mutation tools are omitted from `tools/list` unless experiments are enabled;
- token material is never logged or returned;
- bind remains fixed to `127.0.0.1`.

MCP gains:

```text
cordis_waterfall_experiment_status  # read-only
cordis_start_waterfall_experiment   # mutating, capability-gated
cordis_stop_waterfall_experiment    # mutating cleanup
```

The first tool may be available on read-only MCP. The two mutation tools are capability-gated.

## Shared status/query surface

`RuntimeDiagnosticsQuery` gains a read-only experiment status method so Human UI, DSH inspection, and MCP read paths share the same ownership facts.

`RuntimeDiagnosticsSummary.profiler` may also expose compact ownership metadata, but there remains one canonical detailed status contract.

The diagnostic layer must not claim:

- “the experiment captured everything”;
- “the slow listener is the root cause”;
- “the bug is fixed”.

It returns ownership, expiry, instrumentation state, and retained trace facts only.

## Failure semantics

Expected structured outcomes include at least:

```text
started
busy
unsupported
conflict
stopped
expired
not-active
lease-mismatch
approval-denied       # DSH adapter result/error boundary
unauthenticated       # MCP transport boundary
```

Exact transport error mapping may differ, but runtime state changes only for authoritative `started` / owner-matching `stopped` / timeout cleanup.

## Privacy and security

v0.6 does not weaken metadata-first behavior.

It still does not collect raw event arguments, return values, error messages/objects, prompts, tool outputs, file contents, plugin config, credentials, or raw Effect functions.

The new MCP bearer token is configuration/transport authority and must never enter diagnostic output, snapshots, traces, checkpoints, or logs.

Loopback-only remains mandatory. Authentication is added for external mutation because loopback alone is not an authority boundary against other local processes.

## Real verification scenarios

### DSH approval path

Keyless deterministic test:

```text
real DSH ToolRuntime
  ↓
cordis_start_waterfall_experiment
  ↓
real approval seam returns allowed-once
  ↓
lease active
  ↓
real Cordis waterfall probe
  ↓
trace tagged with experimentId
  ↓
cordis_stop_waterfall_experiment
  ↓
instrumentation disabled
```

A rejected/unavailable approval twin must prove no instrumentation mutation.

### External MCP path

```text
real DSH Host + authenticated MCP
  ↓
start experiment
  ↓
real Cordis waterfall probe
  ↓
read tagged trace
  ↓
stop OR wait for TTL
  ↓
status returns disabled / no active lease
```

Unauthenticated mutation must fail without changing state.

### Human ownership path

The existing Chromium smoke is extended to prove:

- Human profiling still works through the coordinator;
- Human UI renders Agent-owned lease status coherently;
- Human emergency stop terminates an Agent lease safely;
- observer / v0.5 verification regressions remain green.

## Non-goals for v0.6

- automatic source/plugin reload;
- arbitrary Cordis event invocation;
- listener/service/config mutation;
- generic command execution;
- persistent approval grants;
- lease renewal;
- multiple simultaneous profiler leases;
- remote/LAN MCP;
- automatic root-cause `diagnose()`;
- raw payload capture;
- profiling generic emit/parallel/serial/bail modes.

## Completion definition

v0.6 is repository-ready when:

- a single coordinator owns all profiler instrumentation mutation;
- Human and Agent ownership cannot silently overwrite each other;
- Agent leases always have finite expiry and safe cleanup;
- DSH start uses the real one-shot approval seam and fails closed without a grant;
- external MCP mutation is hidden by default and requires explicit capability + bearer auth;
- Agent-created waterfall traces are queryable by experiment id with bounded semantics;
- real DSH tests prove DSH-approved start/trace/stop and authenticated MCP start/trace/timeout-or-stop;
- Human UI/profiler, observer diagnostics, and v0.5 Runtime Verification remain green;
- repository docs/version are closed out only after implementation lands.

npm publication, Git tags, and GitHub Releases remain separate explicit actions.
