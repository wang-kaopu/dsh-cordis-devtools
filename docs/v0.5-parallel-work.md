## First fan-out — checkpoint / diff / fixture

After the transport-neutral contract landed:

- **#42** owned checkpoint projection, scope closure, canonicalization and digest;
- **#43** owned semantic multiset diff;
- **#44** owned only the real Cordis `2 → 1` transition fixture.

They did not compete for `src/host/diagnostics.ts` or the final real-DSH orchestrator. This let all three run CI independently and merge as soon as each was green.

## Integration gate — query composition

**#45** was intentionally sequential. It wired the already-landed checkpoint and diff implementations into the single `RuntimeDiagnosticsQuery` surface:

```text
captureCheckpoint(scope?)
compareCurrent({ baseline })
```

This avoided multiple branches inventing different live-query semantics.

## Second fan-out — DSH / MCP

After #45:

- **#46** changed only the DSH `CordisRuntime` Inspect adapter and its tests;
- **#47** changed only the MCP adapter and official SDK Client tests.

Both delegated to `RuntimeDiagnosticsQuery`. Neither contained its own checkpoint or diff algorithm.

## Final integration — one real DSH process

## Contract correction discovered by integration

The real E2E exposed one semantic mismatch in the original plan: equivalent duplicate listener registrations have distinct runtime registration `order` values.

If `order` participates in the cross-checkpoint Listener semantic key, a real duplicate pair becomes separate count-`1` descriptors and cannot express the intended `2 → 1` multiplicity.

**#49** therefore fixed the final rule:

```text
Listener semantic key
  event
  ownerName / no owner
  prepend
  global

Capture-local evidence only
  listener id
  owner uid
  registration order
```

This is exactly why the final real-runtime integration gate was kept separate from the pure diff tests: it could falsify a plausible contract assumption before repository closeout.

## Auto-merge discipline used

With maintainer authorization active:

- each PR merged only after its required CI was green;
- shared contracts landed before dependent fan-out branches;
- no semantic conflict was resolved by dropping a sibling implementation;
- the final E2E was allowed to feed a contract correction back through #49 before closeout;
- npm publication, Git tag creation, and GitHub Release creation remain outside this repository-closeout workflow.

## Result

The parallel plan achieved the intended product boundary without maintaining competing Agent implementations:
