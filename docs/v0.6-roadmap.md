# v0.6 Roadmap — Controlled Runtime Experiments

v0.6 starts from repository version `0.5.0`, where Human DevTools, DSH Cordis Inspect, and external MCP already share read-only Runtime Diagnostics/Verification semantics.

## Milestone goal

A coding Agent can request one short-lived waterfall profiling experiment, obtain the required authority, collect traces associated with that experiment, and rely on owner-safe timeout cleanup.

v0.6 does **not** generalize this into arbitrary Cordis/runtime mutation.

## Product boundary

Included:

- one shared instrumentation ownership coordinator;
- Human vs Agent ownership semantics;
- finite Agent leases with timeout cleanup;
- experiment-tagged waterfall traces;
- read-only experiment status;
- dedicated DSH Agent start/stop tools;
- DSH one-shot approval before start;
- optional authenticated MCP mutation capability;
- Human emergency stop;
- real DSH approval/MCP/Human regression proof.

Deferred:

- automatic reload;
- arbitrary event execution;
- generic listener/service/config mutation;
- persistent approvals;
- lease renewal;
- multiple simultaneous leases;
- remote MCP;
- payload capture;
- `diagnose()`/root-cause heuristics;
- non-waterfall instrumentation.

## Wave A — Architecture and authority contract

Deliverables:

- [ ] single-owner coordinator boundary fixed;
- [ ] Human/Agent ownership rules fixed;
- [ ] finite lease/timeout semantics fixed;
- [ ] DSH approval boundary fixed;
- [ ] MCP capability/auth boundary fixed;
- [ ] experiment trace association fixed;
- [ ] parallel dependency graph fixed.

Acceptance:

- no Agent can directly toggle the low-level controller;
- no indefinite Agent lease exists;
- external MCP mutation cannot be enabled unauthenticated;
- `CordisRuntime` remains an inspection surface, not a mutation surface.

## Wave B — Shared experiment contract

Small sequential gate before implementation fans out.

Deliverables:

- [ ] transport-neutral status/lease/outcome types;
- [ ] finite TTL input contract;
- [ ] owner/source vocabulary;
- [ ] trace `experimentId` metadata contract;
- [ ] public exports;
- [ ] implemented Agent Note for the finalized contract.

Acceptance:

- types contain no MCP/DSH-specific request objects;
- lease ids are opaque strings;
- contracts can represent busy/conflict/unsupported without inventing success;
- trace tagging remains metadata-only.

## Wave C — Lease coordinator core

Can run after Wave B and in parallel with D/E/F.

Deliverables:

- [ ] `WaterfallExperimentCoordinator` state machine;
- [ ] Human acquire/release;
- [ ] Agent start/stop;
- [ ] finite expiry timer;
- [ ] exact lease ownership checks;
- [ ] Human force-stop;
- [ ] conflict/unsupported propagation;
- [ ] disposal cleanup;
- [ ] deterministic fake-clock tests.

Acceptance:

- stale timeout/stop cannot disable a later owner;
- second start is no-op busy;
- timeout disables only the current matching lease;
- Human emergency stop always works;
- conflict never force-restores another patch.

## Wave D — Experiment trace association

Can run after Wave B in parallel with C/E/F.

Deliverables:

- [ ] optional experiment id on waterfall trace metadata;
- [ ] controller tags traces according to current coordinator context;
- [ ] human traces remain untagged;
- [ ] profiler trace query supports exact `experimentId` filter;
- [ ] bounded-window semantics preserved;
- [ ] late settlement/late `next()` remains associated with the original trace.

Acceptance:

- tagging does not alter listener/waterfall caller-visible behavior;
- traces outside an Agent lease do not inherit stale ids;
- existing parity matrix remains green.

## Wave E — DSH Agent authority adapter

Can begin after Wave B using an abstract experiment-control interface; final wiring waits for integration.

Deliverables:

- [ ] dedicated `cordis_start_waterfall_experiment` tool;
- [ ] dedicated `cordis_stop_waterfall_experiment` tool;
- [ ] start requests one-shot approval before mutation;
- [ ] only `allowed-once` proceeds;
- [ ] absence/rejection/cancellation/unavailable fail closed;
- [ ] stop is exact-lease cleanup without second approval;
- [ ] no mutation method added to `CordisRuntime`.

Acceptance:

- approval is the first meaningful start-body action;
- denied start never touches coordinator mutation;
- stop cannot disable Human/another lease;
- tool registration disposes with plugin lifecycle.

## Wave F — MCP auth/capability adapter

Can begin after Wave B in parallel with C/D/E.

Deliverables:

- [ ] optional bearer auth for embedded MCP;
- [ ] non-empty token required when external experiments are enabled;
- [ ] read-only backward compatibility without experiment capability;
- [ ] mutation tools omitted by default;
- [ ] authenticated start/stop schema/delegation;
- [ ] read-only experiment status tool;
- [ ] official MCP SDK auth/tool-list tests.

Acceptance:

- unauthenticated mutation never reaches coordinator;
- token never appears in output/logs;
- bind remains `127.0.0.1`;
- mutation capability does not silently enable on existing v0.5 config.

## Wave G — Service/control integration

Starts after C + D.

This is the main sequential integration gate.

Deliverables:

- [ ] `DevtoolsService` owns coordinator;
- [ ] low-level controller mutation no longer exposed directly to Human/Agent adapters;
- [ ] existing browser RPC enable/disable routes through Human ownership methods;
- [ ] profiler snapshot/status carries enough ownership data for UI;
- [ ] `RuntimeDiagnosticsQuery` exposes read-only experiment status;
- [ ] DSH `CordisRuntime` exposes read-only status;
- [ ] service disposal delegates coordinator cleanup.

Acceptance:

- exactly one production path owns controller mutation;
- current Human profiling semantics remain behavior-compatible when no Agent lease exists;
- observer/verification paths remain read-only.

## Wave H — Second fan-out: production adapters and UI

Starts after Wave G.

### H1 — DSH native Agent tools

- [ ] wire Wave E adapter to live coordinator;
- [ ] consume real DSH ToolRuntime/approval seam;
- [ ] keyless approved/rejected integration tests;
- [ ] start result returns lease/status facts;
- [ ] stop safely ends exact lease.

### H2 — MCP experiment capability

- [ ] wire Wave F adapter to live coordinator;
- [ ] config validation in plugin entry;
- [ ] authenticated official SDK Client start/status/stop;
- [ ] no-auth / bad-token tests;
- [ ] read-only MCP remains compatible.

### H3 — Human Profiler ownership UX

- [ ] Human enable acquires Human ownership;
- [ ] active Agent lease is visibly identified;
- [ ] expiry is shown as factual metadata;
- [ ] Human emergency stop terminates Agent lease;
- [ ] UI never presents an Agent-owned lease as an ordinary Human toggle session.

Acceptance:

- three adapters share coordinator state rather than maintaining private ownership flags;
- Human can always stop instrumentation;
- DSH/MCP cannot silently steal Human ownership.

## Wave I — Combined real DSH experiment proof

Starts after H1 + H2 + H3.

Scenario:

```text
real DSH
  ↓
DSH tool start
  ↓
real approval = allowed-once
  ↓
Agent lease active
  ↓
real waterfall probe
  ↓
experiment-tagged trace
  ↓
DSH stop
  ↓
disabled

then

authenticated external MCP start
  ↓
real waterfall probe
  ↓
tagged trace
  ↓
TTL expiry or explicit stop
  ↓
disabled

then

Human Profiler enable/trace/disable
  ↓
existing UI + v0.5 verification regression green
```

Required negative twins:

- [ ] DSH approval rejected/unavailable → no mutation;
- [ ] bad/missing MCP token → no mutation;
- [ ] stale lease stop → no mutation;
- [ ] Human force-stop → Agent lease ends safely.

## Wave J — Repository closeout

Only after B–I land.

Deliverables:

- [ ] architecture/product docs planned → implemented;
- [ ] README documents controlled experiment workflow and authority boundaries;
- [ ] roadmap/parallel record updated to actual implementation;
- [ ] `package.json` repository version becomes `0.6.0`;
- [ ] MCP server info becomes `0.6.0`;
- [ ] release-hardening CI all green.

No npm publish, tag, or GitHub Release unless explicitly requested.

## Completion definition

v0.6 is complete at repository level when:

- Waves A–J are satisfied;
- one coordinator owns all instrumentation mutation;
- DSH Agent start is one-shot approved and finite;
- external MCP mutation is explicitly capability-gated and authenticated;
- traces are attributable to the Agent lease that created them;
- Human emergency control remains authoritative;
- real DSH E2E proves positive and fail-closed paths without model/API credentials;
- observer diagnostics, Runtime Verification, Human UI, and waterfall parity remain green.

## Next version boundary

Do not assume v0.7 should add broader mutation. After v0.6, evaluate actual Agent usage first. Possible later directions include automatic reload/verification orchestration or richer experiment types, but each needs a separate authority/lifecycle decision.
