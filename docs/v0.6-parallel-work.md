## First concurrency peak

After #53 fixed transport-neutral lease/status/trace contracts, four sibling workstreams ran independently:

| PR | Workstream | Ownership |
| --- | --- | --- |
| #54 | lease coordinator | owner/TTL/state-machine core |

The important constraint held: none of those branches invented a second ownership model or independently wired the production service.

## Sequential integration gate

#58 was deliberately serialized after coordinator + trace work landed. It made `DevtoolsService` own the coordinator, routed Human browser mutation through it, connected trace attribution to the current lease, exposed read-only status, and centralized disposal cleanup.

This was the point where “single mutation owner” became a production invariant rather than four isolated components.

### MCP sibling integration correction

The first H2 sibling branch touched the same plugin entry after #59/#61 had already landed. Instead of resolving history conflicts by dropping DSH or Human behavior, H2 was rebuilt cleanly from latest `main` and carried only its MCP-specific differences as #62.

That clean rebuild also preserved a compatibility invariant discovered by CI: existing `mcp.enabled: true` continues to expose exactly the original seven read-only tools. Experiment status/start/stop appear only under the explicit experiment capability path.

### Real-session correction

The first #63 run used a session-shaped fake Agent. Real ToolRuntime correctly rejected it because its session was not live in `SessionStore`. The final fixture uses `ctx.sessions.create()` and a real `turn/start`, proving the DSH approval path without bypassing SessionStore or approval audit preconditions.

That failure was treated as useful integration evidence rather than weakened with a mock.

## File ownership lessons

The parallel plan worked because sibling branches avoided central surfaces until their planned integration gate:

- shared experiment vocabulary landed first;
- coordinator and trace tagging stayed separate until #58;
- DSH/MCP authority adapters stayed isolated before live wiring;
- Human UI did not modify coordinator policy;
- final E2E orchestration waited for every production adapter.

The only meaningful sibling collision was the Host plugin entry for DSH/MCP wiring, and it was resolved by rebasing/rebuilding the MCP delta on the already-merged sibling behavior rather than by forcing a three-way compromise.

## Verification by workstream

All landed workstreams were required to keep their smallest focused tests plus the repository CI gate:

- coordinator: fake-clock TTL/ownership/stale-stop/conflict/force-stop matrix;
- trace: attribution, late settlement/`next()`, bounded exact filter, parity regression;
- DSH: approval-first, fail-closed outcomes, exact stop, live registration;
- MCP: bearer auth, capability tool-list behavior, official Client, exact trace filter;
- Human UI: DOM interaction for Agent ownership and emergency stop;
- Wave I: both real DSH smokes in one CI job.

No source-string test was introduced for runtime behavior.
