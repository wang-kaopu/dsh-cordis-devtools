# v0.4 Roadmap — Agent Runtime Diagnostics

This roadmap starts from repository-ready v0.3 behavior. It does not continue the archived v0.2 → v0.3 execution plan.

## Milestone goal

A running DSH/Cordis process exposes the same live runtime diagnostics to:

- developers through the existing Cordis DevTools UI;
- in-process DSH agents through Cordis Inspect;
- external coding agents through an embedded loopback MCP endpoint.

All machine-facing adapters share one Runtime Diagnostics Query layer.

## Wave A — Contract and product boundary

Status: in progress

Deliverables:

- [x] product/design document;
- [x] evidence semantics: live vs historical, bounded vs complete, truncated vs complete query result;
- [x] first read-only query roster;
- [x] DSH Cordis Inspect adapter boundary;
- [x] embedded MCP/loopback security boundary;
- [ ] implementation Agent Notes move to `implemented/` only as their behavior ships.

## Wave B — Runtime Diagnostics Query

Can proceed independently after the contract is fixed.

Deliverables:

- [ ] transport-neutral query types;
- [ ] `runtimeSummary`;
- [ ] `inspectEvent`;
- [ ] `inspectFiber`;
- [ ] `searchDispatches`;
- [ ] `profilerTraces`;
- [ ] pure filtering/ordering/bounded-evidence tests;
- [ ] no new Cordis-internal access outside the existing adapter boundary.

Acceptance:

- callers do not need the full observer/profiler snapshots for common targeted questions;
- result semantics never upgrade bounded evidence into historical certainty.

## Wave C — DSH Cordis Inspect Provider

Depends only on Wave B contract and can run in parallel with MCP work.

Deliverables:

- [ ] register Host provider `CordisRuntime` when `cordisInspect` is available;
- [ ] expose the five read-only query methods with JSON schemas;
- [ ] delegate directly to Runtime Diagnostics Query;
- [ ] lifecycle-owned provider disposal;
- [ ] adapter tests for registration, discovery manifest, delegation, cancellation-compatible shape;
- [ ] real DSH integration coverage where practical.

Acceptance:

- existing DSH `cordis_inspect_list` discovers `CordisRuntime`;
- existing `cordis_inspect_query` can read live runtime diagnostics;
- no duplicate model-facing DSH tool family is introduced.

## Wave D — Embedded MCP Adapter

Depends only on Wave B contract and can run in parallel with Cordis Inspect work.

Deliverables:

- [ ] embedded MCP server owned by the running plugin instance;
- [ ] Streamable HTTP transport;
- [ ] loopback-only bind validation;
- [ ] configured/startup port behavior;
- [ ] five read-only MCP tools matching the logical query roster;
- [ ] disposal closes HTTP/MCP resources;
- [ ] real MCP client integration test for tool discovery and execution;
- [ ] canonical result parity against direct Runtime Diagnostics Query results.

Acceptance:

- an external MCP client can inspect the currently running DSH process rather than a separately created Cordis runtime;
- server startup never silently widens beyond loopback;
- server failure is explicit and does not break observer collection/UI availability unless configuration requires fail-fast behavior.

## Wave E — Agent debugging proof

Begins once either Agent adapter is usable; final proof should cover both.

Fixture scenario:

- create two live Fibers that both own the same event listener while source-level code appears singular;
- ask the Agent-facing interface for evidence without opening the DevTools panel.

Expected evidence chain:

```text
inspectEvent
  → two current listeners
  → two owner uids
inspectFiber(uid A / uid B)
  → both authoritative live Fibers
searchDispatches
  → bounded recent occurrence evidence when applicable
```

Deliverables:

- [ ] deterministic runtime fixture;
- [ ] DSH Cordis Inspect query proof;
- [ ] MCP client proof;
- [ ] documentation showing what runtime evidence adds beyond source inference.

## Wave F — Controlled instrumentation tools

Explicitly deferred until the read-only path is stable.

Candidates:

- `startWaterfallProfiling`;
- `stopWaterfallProfiling`;
- bounded capture session/lease semantics.

Before implementation this wave requires a new decision note covering:

- mutation permission/policy;
- cleanup if the caller disappears;
- conflict/unsupported states;
- whether a time-bounded profiling lease is safer than raw enable/disable tools.

## Parallel execution plan

After Wave B establishes the shared query contract:

```text
                    Runtime Diagnostics Query
                              │
                ┌─────────────┴─────────────┐
                ▼                           ▼
      Wave C: Cordis Inspect       Wave D: MCP Adapter
                │                           │
                └─────────────┬─────────────┘
                              ▼
                    Wave E: Agent proof
```

Documentation and benchmark fixture design can continue alongside all implementation tracks because they do not own production adapter files.

## Intentionally deferred beyond the first v0.4 slice

- profiler mutation tools;
- generic `diagnose()` / confidence heuristics;
- external remote/LAN access;
- stdio proxy/bridge;
- automatic client configuration generation;
- multi-DSH runtime discovery;
- persistent runtime checkpoints/diffs;
- full lossless telemetry or payload capture;
- profiling of non-waterfall modes.
