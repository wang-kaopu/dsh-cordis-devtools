# v0.5 Roadmap — Runtime Verification

Status: **repository-level complete**.

v0.5 was developed from repository version `0.4.0`. The repository closes this milestone at `0.5.0`; npm publication, a Git tag, and a GitHub Release remain separate explicit actions.

## Milestone goal

A coding Agent can:

1. inspect a runtime problem;
2. capture a canonical read-only checkpoint;
3. edit/reload code through the normal development workflow;
4. compare current runtime topology with the caller-held baseline;
5. explain the concrete runtime facts that changed.

The diagnostics package reports facts and mechanical diffs. It does not claim that a bug is fixed or infer root cause.

## Product boundary

v0.5 remains read-only with respect to the target Cordis runtime.

Included:

- versioned self-contained runtime checkpoints;
- exact-name checkpoint scoping;
- deterministic canonical projection and digest validation;
- multiplicity-preserving semantic diff;
- `captureCheckpoint` / `compareCurrent` query methods;
- DSH Cordis Inspect exposure;
- MCP exposure;
- real DSH before/after verification proof through both Agent paths.

Deferred beyond v0.5:

- automatic source/plugin reload control;
- profiler enable/disable Agent tools;
- profiling lease/timeout/permission;
- server-persistent checkpoint storage;
- `diagnose()` / confidence heuristics;
- remote/LAN MCP;
- payload capture.
